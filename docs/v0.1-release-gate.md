# v0.1.0 release gate

Target: the first public preview of n0ding as a read-only pull-through cache for
public npm, PyPI, and Docker Hub content. The supported deployment boundary is
a single operator on localhost or a trusted private network.

Passing this gate means the preview is honest, reproducible, recoverable, and
useful. It does not make n0ding a production supply-chain security platform or
a complete replacement for Nexus Repository and Artifactory.

## Required before tagging

- [x] One canonical `main` branch with required CI.
- [x] Standard npm, pip, uv, and Docker clients have reproducible compatibility
  evidence.
- [x] Cache writes are atomic and OCI plus available PyPI hashes are verified
  before commit.
- [x] Client cancellations, cache failures, and repository errors are reported
  separately.
- [x] Backup and same-version restore are exercised in CI.
- [x] Linux/macOS and Windows installers, a pinned deployment Compose file,
  checksums, upgrade, rollback, and uninstall instructions exist.
- [x] The default deployment binds to loopback and does not silently modify
  package-manager or Docker settings.
- [x] A tag workflow builds AMD64 and ARM64 images, publishes checksums, an
  SBOM, and build provenance.
- [x] The cross-ecosystem release-candidate smoke passes twice across a server
  restart with clean npm, pip, uv, and Docker client state.
- [x] The release workflow receives a no-push multi-architecture build check on
  pull requests.
- [x] Installer behavior is exercised end to end on Linux, macOS, and Windows
  against staged release assets.
- [ ] The uninterrupted seven-day soak completes without corruption, secret
  canary leakage, unexplained errors, or unbounded stale temporary data.
- [x] The capacity-planning rule, 20% warning threshold, 10% critical
  threshold, and accepted age-only-retention risk are recorded.
- [x] README, security policy, compatibility matrix, changelog, and operations
  guide describe the same supported boundary and observed behavior.
- [ ] The canonical GitHub repository is public and private vulnerability
  reporting is enabled before announcing the preview.
- [ ] The exact release commit passes every required check on `main`.

## Supported v0.1.0 boundary

- Public npm registry read-only downloads.
- Public PyPI read-only downloads with pip and uv.
- Public Docker Hub read-only pulls through the OCI Distribution API.
- One n0ding process and one local writable cache volume.
- Localhost or a trusted private network, optionally behind operator-managed
  TLS.
- Best-effort preview support with no availability or remediation SLA.

## Explicitly deferred

These items do not block the preview because v0.1.0 does not claim them:

- package or image publishing;
- n0ding client authentication, users, RBAC, or multi-tenancy;
- real private npm, PyPI, or OCI provider compatibility;
- Maven, NuGet, Helm, generic files, or other repository formats;
- malware scanning, signature policy, provenance enforcement, or vulnerability
  scanning;
- high availability, distributed locking, object storage, or multiple writers;
- strict byte quotas or an availability guarantee;
- Podman support until a dated compatibility run exists.

## Publication control

Completing this checklist makes a commit eligible for a release candidate. It
does not itself authorize creating a tag, publishing a GitHub Release, pushing
an image, or announcing the project. Those remain explicit maintainer actions.
